# «Семицвіт» — сайт и админ-панель

Официальный сайт детского центра «Семицвіт» (Запорожье, ул. Украинская, 4) с системой управления контентом.

**Сайт:** https://zavars296-cyber.github.io/semitsvetik/ · **Админка:** https://zavars296-cyber.github.io/semitsvetik/admin/

## Архитектура

| Часть | Технология |
|---|---|
| Фронтенд | Next.js 15 (static export), React 19, TypeScript, Tailwind CSS, Framer Motion |
| База данных | Supabase PostgreSQL с Row Level Security |
| Вход | Supabase Auth (email + пароль) |
| Фото | Supabase Storage, бакет `media` (сжатие до 1600px WebP и удаление EXIF в браузере) |
| Хостинг | GitHub Pages (работает и на Vercel / Netlify без изменений) |

Сайт статический: HTML собирается заранее со «снимком» контента (для SEO и скорости), а в браузере контент сразу обновляется из Supabase, поэтому изменения из админки видны на сайте мгновенно. Все права проверяются **на сервере** политиками RLS (`supabase/migrations/0001_init.sql`), а не только в интерфейсе. В коде есть только публичный ключ (publishable / anon). Ключ `service_role` / secret не используется нигде и не должен попадать в проект.

```
src/
  app/(site)/        публичные страницы (главная, про нас, программы, педагоги, галерея, новости, дни рождения, контакты, запись, политика)
  app/admin/         админ-панель (14 разделов)
  components/site/   компоненты сайта
  components/admin/  компоненты админки (EntityManager — универсальный редактор)
  lib/               данные, Supabase, авторизация, форматирование, i18n
  content/seed.json  стартовый проверенный контент
supabase/
  migrations/        схема, роли, RLS, хранилище
  seed.sql           стартовый контент
  setup-1/2-*.sql    компактные файлы для вставки в SQL Editor
  tests/             локальный тест прав (27 проверок)
```

## Запуск базы (один раз, ~5 минут)

1. Supabase → **SQL Editor** → New query → вставить весь файл [`supabase/setup-1-schema.sql`](supabase/setup-1-schema.sql) → **Run** (ответ `STEP 1 OK`). Затем так же [`supabase/setup-2-content.sql`](supabase/setup-2-content.sql) (`STEP 2 OK`). Файлы можно запускать повторно, данные не затираются.
2. **Authentication → Users → Add user → Create new user**: email и пароль владельца (от 10 символов), галочка **Auto Confirm User**.
3. Снова SQL Editor: `select public.make_owner('email@владельца');` → Run. Ответ `OK: ...`.
4. **Authentication → URL Configuration → Site URL**: `https://zavars296-cyber.github.io/semitsvetik/admin/` (нужно для писем подтверждения и сброса пароля).
5. Войти на `/admin/`. Сотрудники регистрируются там же кнопкой «Я новий працівник», владелец выдаёт им роль в разделе «Користувачі та права».

Владелец создаётся только через SQL Editor: пароли нигде не хранятся в коде, а функция `make_owner` недоступна с сайта.

## Защита
- RLS на всех таблицах; публичные пользователи видят только опубликованное.
- Форма записи: проверка полей в браузере и в базе, honeypot, защита от слишком быстрой отправки, лимит 3 заявки с номера в сутки и 60 в час всего.
- Фото с детьми нельзя опубликовать без отметки о согласии родителей (ограничение в базе).
- Отзывы можно опубликовать только с отметкой «перевірено».
- Нельзя удалить или понизить последнего владельца.
- Журнал действий (кто и что изменил).

## Резервные копии
Бесплатный Supabase не делает бэкапы автоматически. Раз в месяц: Supabase → Database → Backups (на платном тарифе) или SQL Editor → выгрузить таблицы в CSV; заявки выгружаются кнопкой «Завантажити CSV» в админке. Фото лежат в Storage → `media`.

## Разработка
```bash
cp .env.example .env.local   # заполнить URL и publishable key
npm install
npm run dev                  # http://localhost:3000/semitsvetik
npm run build                # статическая сборка в out/
```
Без ключей Supabase админка работает в демо-режиме (данные в браузере).

Тест прав (нужен локальный PostgreSQL 16):
```bash
psql -f supabase/tests/mock_supabase.sql && psql -f supabase/migrations/0001_init.sql && psql -f supabase/tests/rls_test.sql
```

## Деплой
Каждый push в `main` собирает сайт GitHub Actions и публикует в ветку `gh-pages`. Раз в сутки сборка повторяется, чтобы обновить SEO-снимок контента.

**Vercel (по желанию):** импортировать репозиторий, задать переменные из `.env.example`, `NEXT_PUBLIC_BASE_PATH` оставить пустым, `NEXT_PUBLIC_SITE_URL=https://semitsvetik.vercel.app`. В Supabase добавить новый адрес в Authentication → URL Configuration.

**Добавить язык:** словарь интерфейса в `src/lib/i18n.ts`; контент хранится в полях таблиц, для второго языка добавляются поля `*_en` или отдельные строки.
